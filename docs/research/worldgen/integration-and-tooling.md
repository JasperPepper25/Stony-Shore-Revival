# Integration libraries, volumetric engines, and inspection tooling

[Research index](README.md)

Research date: 2026-10-09. This chapter reviews source code and official documentation to identify methods relevant to Stony Shore Revival's beaches, ocean-facing arches and overhangs, and contained shelf pools. It changes neither the V9 implementation nor its dependencies.

**Evidence convention:** **Observed** describes inspected implementation; **Inference** connects that implementation to our design; **Experiment** proposes work that still needs measurement or visual validation. Source inspection does not establish that a method is faster in our mod or that it will produce the desired appearance.

## Lithostitched: how V9's actual integration works

### Router composition happens before seeding

**Observed.** In 1.4.11, Lithostitched redirects the `RandomState.create` call in the `ChunkMap` constructor. It gathers matching dimension modifiers and wraps the selected noise-router fields before Minecraft constructs the seeded random state. Router wrappers are sorted by increasing integer priority; each subsequent wrapper receives the previous result, making a higher-priority wrapper outermost. Equal priorities have no explicit secondary ordering in this implementation. Sources: [ChunkMapMixin](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/mixin/common/ChunkMapMixin.java), [WrapNoiseRouterModifier](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/worldgen/modifier/WrapNoiseRouterModifier.java).

**Inference.** This is a suitable place to compose a coastal terrain node: the upstream Tectonic/Terralith graph remains available, and Minecraft can seed the composed graph as one unit. Replacing noise nodes after seeding would require additional proof that the new graph's noises, caches, and preliminary-surface queries remain consistent. V9 already uses the supported pre-seeding wrapper path with priority 1100. Sources: [V9 final-density modifier](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/resources/data/stonyshorerevival/lithostitched/worldgen_modifier/coastal_final_density.json), [V9 native integration](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/java/com/fineedge/stonyshore/terrain/CoastalTerrainIntegration.java).

### The marker determines whether other mods survive composition

**Observed.** `wrapped_marker` resolves to the current wrapped result, whereas `original_marker` can recover the original root below earlier wrappers. A wrapper without an appropriate marker may replace the input rather than preserve it. `MergedDensityFunction` delegates runtime computation to its full composition, but serializes the original function; wrappers are reconstructed by the loader. Sources: [DensityFunctionWrapper](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/worldgen/modifier/util/DensityFunctionWrapper.java), [MergedDensityFunction](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/worldgen/densityfunction/MergedDensityFunction.java).

**Inference.** V9's use of `wrapped_marker` is important compatibility behavior, not interchangeable syntax. Save/reopen tests should verify that exactly one coastal node is reconstructed in each target router, with the same upstream input and output. A successful initial world creation alone does not verify that lifecycle.

### Modifier ordering is not one universal pipeline

**Observed.** The general modifier framework has ordered phases, applies non-priority modifiers before priority modifiers within a phase, and skips `NONE` in ordinary application. Router wrapping uses its separate construction hook. `wrap_density_function` modifies a registered density-function holder; it is distinct from wrapping a router field. Surface-rule collection does not use the router wrapper's explicit priority sort. Sources: [Modifier](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/worldgen/modifier/Modifier.java), [WrapDensityFunctionModifier](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/worldgen/modifier/WrapDensityFunctionModifier.java), [SurfaceRuleManager](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/worldgen/surface/SurfaceRuleManager.java).

**Inference.** Do not assume priority 1100 also controls Forge feature-list insertion or all surface rules. For beach material ownership, prefer an explicit, bounded coastal material decision and verify its precedence against upstream surface rules. Reordering an unrelated modifier is not a reliable fix for grass returning to a beach.

### Adding biome features does not enlarge a biome

**Observed.** Forge 1.4.11 `AddFeaturesModifier` delegates to Forge's biome feature-list modifier. Its operation adds features at a generation step; it does not rewrite climate parameters or biome-source placement. The version's common density registration is also much smaller than the modern library's feature set. Sources: [Forge AddFeaturesModifier](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/forge/src/main/java/dev/worldgen/lithostitched/worldgen/modifier/AddFeaturesModifier.java), [LithostitchedCommon](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/LithostitchedCommon.java).

**Inference.** A nearby ocean column can receive coastal terrain through a density influence mask while retaining its ocean biome. That is separate from increasing stony-shore biome prevalence. Our V9 offshore envelope already takes the first approach. It preserves climate selection while allocating seaward space to the arch, beach apron, and shallow-water transition. The material and ecology passes must follow the same influence boundary where needed.

### Density-aware placement has a setup cost to investigate

**Observed.** `SampleDensityPlacementCondition` creates a new `NoiseWiringHelper`, maps the selected density function, then samples one position for each condition test. The helper memoizes graph nodes only within that traversal and obtains seeded noises from the current `RandomState`. `NoiseSlopePlacement` converts a noise value through a count slope and offset; the name does not mean it measures physical terrain slope. Sources: [SampleDensityPlacementCondition](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/worldgen/placementcondition/SampleDensityPlacementCondition.java), [NoiseWiringHelper](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/worldgen/NoiseWiringHelper.java), [NoiseSlopePlacement](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/worldgen/placementmodifier/NoiseSlopePlacement.java).

**Experiment.** If we adopt density-aware decoration predicates, count graph mappings separately from density samples. Cache a wired immutable graph only with a correct random-state/world/generator context. Never introduce a global seeded graph merely to avoid construction cost. For moss and pool decorations, a cached coastal landform plan may be a cheaper predicate than repeatedly rebuilding a large general graph; this needs measurement.

### Conditional loading is useful for optional integrations

**Observed.** The registry loader first decodes load predicates through a no-op modifier and can replace an inactive entry before parsing its complete payload. This helps optional integrations whose payload contains registry references unavailable without another mod. Source: [RegistryDataLoaderMixin](https://github.com/Apollounknowndev/lithostitched/blob/bc8029471a7e4b2f00a2091d287d781397408a25/common/src/main/java/dev/worldgen/lithostitched/mixin/common/RegistryDataLoaderMixin.java).

**Inference.** Optional modifier files should carry explicit load conditions instead of relying on runtime exception recovery after missing references have already been decoded. This complements, rather than replaces, V9's runtime adapter checks.

## What modern Lithostitched adds—and why it is not a V9 drop-in answer

**Observed.** The inspected 1.8.0 branch has a biome injector manager that wraps the existing biome source and rebuilds feature ordering with `FeatureSorter`. Its injector source preserves a root delegate for serialization, supports multiple placement/replacement forms, and has explicit accommodations for Blueprint and TerraBlender internals. These are conditional compatibility paths, not proof of arbitrary mod-stack compatibility. Sources: [BiomeInjectorManager](https://github.com/Apollounknowndev/lithostitched/blob/38779fe2059d33cc92d9b8012c6eb73bfcaaac96/src/main/java/dev/worldgen/lithostitched/impl/worldgen/biomeinjector/internal/BiomeInjectorManager.java), [InjectorBiomeSource](https://github.com/Apollounknowndev/lithostitched/blob/38779fe2059d33cc92d9b8012c6eb73bfcaaac96/src/main/java/dev/worldgen/lithostitched/impl/worldgen/biomeinjector/internal/InjectorBiomeSource.java).

**Inference.** If a future port adopts biome-source wrapping, the integration contract must account for the wrapper's delegate and possible-biome set, then revalidate feature ordering. V9 currently requires `MultiNoiseBiomeSource` and exact supported dependency versions. That conservative gate is consistent with its present scope; it would intentionally reject a different wrapper type. Supporting newer sources requires an explicit adapter, not weakening the check without equivalent evidence.

**Observed.** Modern `MapAllCache` memoizes density-graph transformations using thread-local, visitor-scoped identity maps. Nested operations push/pop state, and the outermost completion clears it. This is traversal memoization, not a global cache of sampled terrain values. Sources: [MapAllCache](https://github.com/Apollounknowndev/lithostitched/blob/38779fe2059d33cc92d9b8012c6eb73bfcaaac96/src/main/java/dev/worldgen/lithostitched/impl/worldgen/densityfunction/MapAllCache.java), [DensityFunctionsMapAllMixin](https://github.com/Apollounknowndev/lithostitched/blob/38779fe2059d33cc92d9b8012c6eb73bfcaaac96/src/main/java/dev/worldgen/lithostitched/mixin/common/density/DensityFunctionsMapAllMixin.java).

**Experiment.** Profile graph traversal separately from repeated per-column coastal planning. Traversal memoization will not automatically fix the latter. If implemented locally, its lifetime must be scoped so it cannot retain obsolete worlds or incorrectly reuse results across visitors.

## Terra: broad elevation plus volumetric shape, with separate carving

**Observed.** Terra's noise generator combines a 3D interpolated terrain sampler with a 2D elevation interpolator. The generator tests base terrain before evaluating a separate carver, chooses palettes by biome and local density-gradient slant, and treats ground material depth as a generation concern distinct from the density itself. Sources: [Sampler3D](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/addons/chunk-generator-noise-3d/src/main/java/com/dfsek/terra/addons/chunkgenerator/generation/math/samplers/Sampler3D.java), [NoiseChunkGenerator3D](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/addons/chunk-generator-noise-3d/src/main/java/com/dfsek/terra/addons/chunkgenerator/generation/NoiseChunkGenerator3D.java).

**Inference.** This reinforces a useful division for our mod: use a coherent height/elevation profile for beaches and shallow seas, a bounded volumetric addition for cliff lips and projecting rock fins, then limited erosion/opening operations on those forms. A deep cave or shaft should not be the prerequisite for an overhang. A material palette should react to exposed spans and landform ownership rather than determine the rock shape.

**Observed.** Terra samples its base density on a four-block grid and interpolates between anchors. At each anchor, terrain samplers from nearby biomes are blended with normalized weights; neighborhood biome columns are reused. Its carver uses a lazy interpolator with independently configurable horizontal and vertical resolutions, evaluating anchor values on demand. Sources: [ChunkInterpolator](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/addons/chunk-generator-noise-3d/src/main/java/com/dfsek/terra/addons/chunkgenerator/generation/math/interpolation/ChunkInterpolator.java), [LazilyEvaluatedInterpolator](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/addons/chunk-generator-noise-3d/src/main/java/com/dfsek/terra/addons/chunkgenerator/generation/math/interpolation/LazilyEvaluatedInterpolator.java), [configuration defaults](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/addons/chunk-generator-noise-3d/src/main/java/com/dfsek/terra/addons/chunkgenerator/config/NoiseChunkGeneratorPackConfigTemplate.java).

**Inference.** Interpolation is a deliberate quality/cost tradeoff, not a guarantee of smooth terrain. Thin lips, small pool rims, or narrow portals can disappear or move when their scale approaches anchor spacing. Our tests should exercise translated versions of the same landform across every interpolation-cell offset.

**Observed.** Terra's `SamplerProvider` bounds cached per-chunk samplers and keys them by chunk coordinates, seed, and vertical bounds. Its experimental `CacheSampler` instead uses thread-local caches, including a large configured 3D entry limit. Sources: [SamplerProvider](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/addons/chunk-generator-noise-3d/src/main/java/com/dfsek/terra/addons/chunkgenerator/generation/math/samplers/SamplerProvider.java), [CacheSampler](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/addons/config-noise-function/src/main/java/com/dfsek/terra/addons/noise/config/sampler/CacheSampler.java).

**Experiment.** Try chunk-local or last-column memoization for repeated Y samples before increasing shared cache capacity. Thread-local caches reduce sharing but multiply memory by worker count and can retain worlds; capacity, cleanup, and actual allocation must be measured.

**Observed.** Terra's biome pipeline has explicit border replacement and a neighborhood smoothing stage. The latter can replace a center when opposing neighbors agree; it smooths categorical biome pixels, not density values. Official documentation also exposes domain warp as a biome-layout operation. Sources: [BorderStage](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/addons/biome-provider-pipeline/src/main/java/com/dfsek/terra/addons/biome/pipeline/stage/mutators/BorderStage.java), [SmoothStage](https://github.com/PolyhedralDev/Terra/blob/25d510156de02cb77f8fb6ffde276417eb19aea4/common/addons/biome-provider-pipeline/src/main/java/com/dfsek/terra/addons/biome/pipeline/stage/mutators/SmoothStage.java), [official pipeline guide](https://terra.polydev.org/config/development/pack-from-scratch/pipeline.html).

**Inference.** An explicit coastal influence band and gradual density transition can solve space allocation without wholesale biome replacement. If our categorical shore mask is jagged, smoothing the downstream heightfield alone may hide rather than resolve inconsistent classification.

## Iris: gated volumetric cliffs and span-aware finishing

**Observed.** Iris's optional volumetric terrain preserves the broad base height while adding bounded 3D displacement and fissures. Its runtime scales this effect using smooth elevation and slope gates, limits the vertical sampling band, and preserves terrain at or below the fluid level. Anchors are four blocks apart; noise samples within the band are lazy. Sources: [Terrain3DRuntime](https://github.com/VolmitSoftware/Iris/blob/d480abad501b8692e8948f49319882a18ab85850/core/src/main/java/art/arcane/iris/generation/terrain/Terrain3DRuntime.java), [official volumetric terrain chapter](https://github.com/VolmitSoftware/docs/blob/b29fb756930b6fa60f19104d0ac874eb59ff6b18/iris/47-volumetric-terrain.md).

**Inference.** Smooth eligibility gates can keep dramatic cliffs local while preserving gentle beaches. The ocean-facing direction should still come from an explicit coast normal; unrestricted isotropic 3D noise alone does not ensure seaward arches. Iris's below-fluid preservation cannot be copied wholesale because our project deliberately changes the nearshore seabed. Separate beach/apron and cliff-volume branches fit our goals better.

**Observed.** Iris represents multiple solid spans in a column after shaping. Its documentation distinguishes top-height queries from lower shelf floors and treats exposed ledges/undersides as separate finishing surfaces. Source: [volumetric terrain documentation](https://github.com/VolmitSoftware/docs/blob/b29fb756930b6fa60f19104d0ac874eb59ff6b18/iris/47-volumetric-terrain.md).

**Inference.** Once a projecting arch or lip creates several surfaces in one X/Z column, a single highest-ground query cannot describe every valid pool shelf or decoration surface. Pool placement should operate on selected supported spans or a landform plan, with rim/floor checks against the final density. This is especially relevant to the user's elevated pool examples.

**Observed.** Iris includes a bounded connected-span filter: it traverses horizontal neighbors and overlapping vertical spans, removes small disconnected fragments up to a limit, and keeps components exceeding its 512-voxel bound. It uses reusable thread-local scratch and clears retained references after traversal. Sources: [Terrain3DFragmentFilter](https://github.com/VolmitSoftware/Iris/blob/d480abad501b8692e8948f49319882a18ab85850/core/src/main/java/art/arcane/iris/generation/terrain/Terrain3DFragmentFilter.java).

**Inference.** A size-limited filter removes small floaters; it does not prove that every retained mass attaches to the parent cliff. For our sparse arches and lips, validating each planned feature's root and minimum rock thickness may be more targeted than flood-filling all generated terrain. Reject a candidate whose connection fails instead of repairing it through an unbounded shaft.

**Observed.** Iris uses bounded concurrent caches and a thread-local last-column memo with generation identity. The cache implementation is a lossy, set-associative CLOCK design with atomic insertion and bounded storage. Sources: [Terrain3DRuntime](https://github.com/VolmitSoftware/Iris/blob/d480abad501b8692e8948f49319882a18ab85850/core/src/main/java/art/arcane/iris/generation/terrain/Terrain3DRuntime.java), [ConcurrentClockCache](https://github.com/VolmitSoftware/Iris/blob/d480abad501b8692e8948f49319882a18ab85850/core/src/main/java/art/arcane/iris/generation/cache/ConcurrentClockCache.java).

**Experiment.** Compare a small last-column memo, a bounded concurrent shared cache, and our existing synchronized LRU using representative chunk-generation traces. Lossy caches must affect only cost, never terrain output. This source design is evidence of an alternative, not evidence of a speedup for us.

## Additional tools and historical approaches

### More Density Functions: useful experimental vocabulary, cautious adoption

**Observed.** The inspected 1.20.1 version registers coordinate, trigonometric, distance, value/Worley/Voronoi noise, derivative, resolver, and profiler nodes. The derivative computes finite differences, requiring two argument samples per active axis plus direction evaluation. Sources: [registrations](https://github.com/klinbee/More-Density-Functions/blob/33c9bcca96953a5a1aa1862b844b614d6697ca70/common/src/main/java/com/klinbee/moredensityfunctions/registration/CommonRegistrations.java), [Derivative](https://github.com/klinbee/More-Density-Functions/blob/33c9bcca96953a5a1aa1862b844b614d6697ca70/common/src/main/java/com/klinbee/moredensityfunctions/densityfunctions/Derivative.java).

**Inference.** These operations support prototyping irregular rock masks and slope predicates in data. They do not make a derivative cheap, nor establish that cellular noise is appropriate for our large coastline contours. We can prototype the useful mathematics independently before requiring another runtime mod.

**Observed.** Its profiler repeatedly computes at one position, explicitly calls garbage collection, then disables itself through a global identity set. Its resolver stores mapped functions in a global identity-keyed map. Random samplers read a static volatile world-seed holder, overwritten by a `ChunkMap` construction hook. Sources: [Profiler](https://github.com/klinbee/More-Density-Functions/blob/33c9bcca96953a5a1aa1862b844b614d6697ca70/common/src/main/java/com/klinbee/moredensityfunctions/densityfunctions/Profiler.java), [Resolver](https://github.com/klinbee/More-Density-Functions/blob/33c9bcca96953a5a1aa1862b844b614d6697ca70/common/src/main/java/com/klinbee/moredensityfunctions/densityfunctions/Resolver.java), [RandomSampler](https://github.com/klinbee/More-Density-Functions/blob/33c9bcca96953a5a1aa1862b844b614d6697ca70/common/src/main/java/com/klinbee/moredensityfunctions/randomsamplers/RandomSampler.java), [ChunkMapMixin](https://github.com/klinbee/More-Density-Functions/blob/33c9bcca96953a5a1aa1862b844b614d6697ca70/common/src/main/java/com/klinbee/moredensityfunctions/mixin/ChunkMapMixin.java).

**Inference.** Its profiler is a local computation probe, not an authoritative chunk-throughput benchmark. Global seed/cache ownership warrants multi-world, reload, and mapped-visitor testing before dependency adoption. This is a source-backed risk to verify, not a claim that every ordinary installation fails.

### Graph and slice visualization

The [Density Function Editor](https://github.com/jacobsjo/density-function-editor/blob/9b54db501c404a5b2d021b7296dd41a950a61663/Readme.md) provides graphical editing. Its [preview code](https://github.com/jacobsjo/density-function-editor/blob/9b54db501c404a5b2d021b7296dd41a950a61663/src/main/UI/PreviewMode.ts) samples top and vertical profile slices through Deepslate and can color solid/empty density signs.

**Experiment.** Use such tools for vanilla-compatible density fragments and composition diagrams. For our Java coastal node, export deterministic in-mod or test-harness slices: baseline/final density, shore classification, coast normal, influence weight, and selected surface spans. A generic browser preview should not be treated as a simulation of our custom node, aquifer, surface rules, or full mod stack.

### OpenTerrainGenerator: transition parameters and feature footprints

**Observed.** The inspected 1.16 branch blends nearby biome height, volatility, and other terrain parameters using a precomputed spatial weight table. It computes a selector before choosing whether one or both expensive interpolated noise branches are necessary. Source: [OTGChunkGenerator](https://github.com/PG85/OpenTerrainGenerator/blob/b9d2d644e704487e389ee975fd92ea9cc8a59872/common/common-core/src/main/java/com/pg85/otg/gen/OTGChunkGenerator.java).

**Inference.** Blend landform parameters over space instead of alternating large, rigid biome-sized templates. Evaluate cheap eligibility/selection before expensive branches where output equivalence permits. The source's own speed claim was not independently validated here and is not a performance estimate for our mod.

**Observed.** BO4 smoothing plans terrain transitions around exposed object edges, accounts for connected object branches, stores affected lines by chunk, and resolves terrain endpoints later. It supports both filling low surroundings and cutting high surroundings. Source: [SmoothingAreaGenerator](https://github.com/PG85/OpenTerrainGenerator/blob/b9d2d644e704487e389ee975fd92ea9cc8a59872/common/common-customobject/src/main/java/com/pg85/otg/customobject/structures/bo4/smoothing/SmoothingAreaGenerator.java).

**Inference.** Feature integration should budget a footprint around the feature, not only its visible blocks. However, linear endpoint slopes and cardinal edge tracing can reproduce the straight outlines we want to eliminate. For an arch, a curved root transition and bounded density influence are more promising than importing this block-placement algorithm.

## V9 review: what the evidence supports changing next

V9 already establishes the most important architecture: a seeded upstream density input, explicit ocean extension, bounded projections, scoped caches, and conservative failure behavior. The research supports refining these components before replacing the generator. Sources: [NativeCoastalDensity](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/java/com/fineedge/stonyshore/terrain/NativeCoastalDensity.java), [NativeCoastalModel](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/java/com/fineedge/stonyshore/terrain/NativeCoastalModel.java), [CoastalProjection](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/java/com/fineedge/stonyshore/terrain/CoastalProjection.java).

1. **Check classification before adding more shape noise.** V9 classifies biome samples on a four-block lattice, builds boundary nodes on an eight-block lattice, reconstructs baseline heights from a sixteen-block lattice, and interpolates the resulting distances. The closest shore anchor is selected from boundary neighbors. **Inference:** narrow shoreline changes and anchor switches are possible sources of visible contour changes; this is not a demonstrated cause of the V8 screenshots. Compare these masks against dense samples and render both before tuning another noise layer. [NativeCoastalModel](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/java/com/fineedge/stonyshore/terrain/NativeCoastalModel.java)

2. **Keep smooth attachment local.** V9 uses positive-solid sign fields, minimum operations inside primitives, maximum union for fins/lips, and a linear mask blend into the original terrain. **Inference:** a bounded smooth union could soften roots, but these functions are not automatically true distance fields. Arbitrary smooth-min formulas or mismatched scales can thicken portals, flatten rims, or move cliff surfaces. Normalize the intended transition scale and test the attachment before changing composition globally. [CoastalShape](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/java/com/fineedge/stonyshore/terrain/CoastalShape.java), [CoastalProjection](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/java/com/fineedge/stonyshore/terrain/CoastalProjection.java)

3. **Measure cache work where it occurs.** V9's bounded access-order LRU synchronizes hits, performs expensive factories outside its monitor, and permits duplicate concurrent misses. The density wrapper computes its original input before testing the coastal cap and directly fills arrays through scalar sampling. **Experiment:** record hit rates, duplicate factories, allocation, lock wait, and time per generated chunk before replacing the cache or altering evaluation order. A fast outside-mask path is useful only if it preserves blender/failure/baseline semantics. [BoundedCache](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/java/com/fineedge/stonyshore/terrain/BoundedCache.java), [NativeCoastalDensity](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/java/com/fineedge/stonyshore/terrain/NativeCoastalDensity.java)

4. **Reserve pool support after volumetric shaping.** A smooth broad height profile is useful, but a top-height reconstruction does not identify every lower ledge beneath an overhang. **Experiment:** evaluate final solid spans in a planned pool footprint and reject candidates without a supported floor and closed rim. Use separate acceptance checks for water level, depth, footprint, and surface material; do not infer a valid pool from a top height alone. [CoastalProfile](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/java/com/fineedge/stonyshore/terrain/CoastalProfile.java), [NativeCoastalModel](https://github.com/JasperPepper25/Stony-Shore-Revival/blob/c61270e946adcf06f57ff60c82d90cb3303271b2/src/main/java/com/fineedge/stonyshore/terrain/NativeCoastalModel.java)

## Proposed experiments and acceptance checks

| Priority | Experiment | Evidence to collect / acceptance |
| --- | --- | --- |
| 1 | Full-stack router lifecycle audit on the exact supported versions | Create, save, reopen, and generate adjacent chunks. Exactly one coastal node per target field; upstream wrappers preserved; deterministic samples and no newly introduced seams. |
| 1 | Classification and interpolation atlas | Render dense truth against 4/8/16-block planning grids for narrow shores, concave coves, and diagonal coasts. Translate fixtures across all cell offsets; explain every discontinuity before choosing a finer grid. |
| 1 | Arch/lip root validation | Check connected rock support, minimum thickness, ocean-facing orientation, bounded affected volume, open portal, and absence of vertical repair shafts. Include chunk-edge and highly curved shore fixtures. |
| 1 | Span-aware pools | Compare low, middle, and elevated supported shelves. Closed rims, shallow bounded bottoms, stable water, expected size/frequency, and no spill into arch portals or underside air. |
| 2 | Local root smoothing | Compare hard union with a bounded blend in consistent units. Portal area and roof thickness remain within design limits; unrelated beach and pool geometry unchanged outside the transition footprint. |
| 2 | Cache and evaluation benchmark | Fixed seeds, fixed chunk sets, cold/warm runs, representative worker counts. Report wall time, density probes, duplicate factories, cache memory, allocation, and p95 chunk time; verify identical terrain hashes. |
| 2 | Multi-world and teardown tests | Same coordinates in different seeds/dimensions; alternating world loads; concurrent generation; retained-reference checks after unloading. No cross-world result reuse. |
| 3 | Optional density-tool sandbox | Test MDF graph lifecycle and noise seeding before any dependency decision. Use a real generation profiler in addition to one-point probes. |

Run performance experiments on controlled generation workloads with competing background generation disabled. The Distant Horizons progress text in screenshots is not an isolated measurement of this mod's cost.
